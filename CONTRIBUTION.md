# Contribuer à MealPlanner

Ce document décrit le flux de contribution au projet MealPlanner. Le projet est organisé en deux parties, `front/` et `back/`. Consultez le README correspondant avant de travailler sur l'une d'elles.

## Proposer une modification

1. Partez de la branche principale à jour et créez une branche dédiée à votre changement.
2. Choisissez un nom explicite, par exemple `feat/meal-planning` ou `fix/recipe-validation`.
3. Limitez chaque changement à un objectif cohérent et gardez les deux parties de l'application synchronisées lorsque leurs contrats évoluent.
4. Vérifiez les changements avant de les partager et indiquez les vérifications effectuées. Si une vérification n'a pas pu être faite, précisez-le.
5. Ouvrez une pull request décrivant le besoin, la solution, les impacts éventuels sur l'API ou les données, et les étapes de validation.

## Contenu attendu d'une pull request

- Un titre court qui décrit le changement.
- Un résumé du comportement ajouté ou corrigé.
- Les éventuels changements de configuration ou de données nécessaires.
- Des captures d'écran pour les changements visibles dans l'interface, si cela est utile.
- Une liste des vérifications réalisées.

## Principes de contribution

- Suivez les règles de `GUIDELINES.md`.
- Préservez les données personnelles de chaque utilisateur : recettes, planning et listes de courses doivent rester associés à leur propriétaire.
- N'ajoutez pas de secrets, de mots de passe ou de données personnelles au dépôt.
- Mettez à jour la documentation lorsque le comportement ou l'utilisation du projet change.
- Préférez des changements lisibles et ciblés, avec des noms explicites et des erreurs compréhensibles.
